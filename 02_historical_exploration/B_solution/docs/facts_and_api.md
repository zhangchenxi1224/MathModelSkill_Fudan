# B 题事实依据与通信协议

本文件按本地 `B题/B题.pdf` 的完整 4 页、`B题/附件/附件1.docx` 和 `附件2.docx` 核对。便于检索的正文及表格抽取存于 `B_solution/sources/`。协议实现没有读取、解密、反编译或访问官方隐藏案例。本地模拟器是独立测试环境，不能替代官方演练或正式测试。

## 题设事实到数学与接口的对应

以下表用于逐项审计模型依据；“数学表达”是对题设的形式化，不代表接口额外提供这些隐藏量。记源位置为 g、机器人请求位置为 q、源接收半径为 R、定向单位向量为 d。

| 题设事实 | 数学表达 | 接口表现 | 原始来源 |
|---|---|---|---|
| 源在目标圆内，机器人可出圆 | `||g||≤1800`；`abs(q_x),abs(q_y)≤2000000` | 两行动端点接受域外有限坐标，移动照常计费 | PDF 第 1、4 页；附件 2 §1.1 |
| 频道唯一，数量未知 | `N∈{10,…,16}`，每 `f∈{1,…,20}` 至多一源 | 请求指定单一 `channel`，响应不返回 N | PDF 附录 1；附件 2 §1.3 |
| 各源有效半径固定但未知 | `1000≤R≤1500` | 距离超过 R 为 `no_signal`，接口不返回 R | PDF 附录 2(2)；附件 2 §2.1 |
| 全向源在范围内可见 | `||q−g||≤R` | 满足条件时返回 `direction` 或 `near` | PDF 附录 1；附件 2 §2.2、7.3 |
| 定向源为 180° 闭覆盖 | `||q−g||≤R` 且 `d·(q−g)≥0`，非零位移时 | 背向也可产生 `no_signal`，不能直接作整圆排除 | PDF 附录 1(3)；附件 2 §2.2 |
| 有界方向误差且固定点误差不变 | `abs(wrap(theta−arg(g−q)))≤1°`，同位置误差固定 | `svd_deg` 是含误差示向度，保留两位小数 | PDF 附录 2(1)；附件 2 §2.3、7.3 |
| 信号过强不返回方向 | `||q−g||≤5` 且位于辐射范围 | `measure_result="near"`，无 `svd_deg` | PDF 附录 2(9)；附件 2 §2.4 |
| 光学清除只依赖距离 | 未清除源满足 `||q−g||≤20` | `/clear` 返回 `success`，无需无线电可见；否则 `no_target_in_range` | PDF 附录 2(8)；附件 2 §8.2 |
| 移动、测向、切换和清除成本 | `T=L/5+5M+S+5K+3F` | `/measure` 更新测向频道；`/clear` 不换频道；失败清除也移动且花 3 秒 | 附件 1 §2；附件 2 §4、§10 |
| 只接受串行动作，同 ID 同内容幂等 | 同一逻辑动作至多推进一次状态 | 重试复用原 ID/内容；冲突或并发为 HTTP 409 | 附件 2 §1.4、5.3、12 |
| 拒绝动作不生效 | `state_after=state_before` | `accepted=false` 的 `virtual_time_s=0` 是拒绝占位值 | 附件 2 §4.1、5.2 |
| 真实与虚拟时限不同 | 真实截止为窗口截止与进入后 20 分钟的较早者；虚拟≤100小时 | `/enter` 返回实际 `remaining_real_duration_s`；结束后连接可关闭 | PDF 附录 3；附件 2 §4.5、6.2 |

对定向源的零位移 d·0=0 属于形式上的闭半平面边界，但题面未明确零向量方位的处理；本地零距离约定见下文，覆盖证明使用非重合正距离测点。

## 四个正式端点

默认地址 `http://127.0.0.1:2026`，只监听本机回环地址。必须先在官方界面登录并启动测试，待接口就绪后才调用。客户端的导入、构造和本地日志关闭均不会发送官方请求。

所有请求为 POST。请求头采用 `Content-Type: application/json; charset=utf-8`，不压缩。请求体为无 BOM 的 UTF-8 JSON 对象，最大 65536 字节、最大嵌套 16 层、不能出现重复键。

| 路径 | 请求字段 | 成功响应的附加字段 |
|---|---|---|
| `/enter` | `arena_id`, `robot_id`, `request_id` | `max_virtual_duration_s`, `max_real_duration_s`, `remaining_real_duration_s` |
| `/measure` | 公共字段加 `position: {x,y}`, `channel` | `measure_result`；只有 `direction` 带 `svd_deg` |
| `/clear` | 公共字段加 `position: {x,y}`, `channel` | `clear_result` |
| `/exit` | `arena_id`, `robot_id`, `request_id` | `exit_reason: "user_exit"` |

所有业务响应至少含 `accepted`、`real_timestamp_ms`、`virtual_time_s`。`arena_id` 固定为 `"default"`。`robot_id` 必须与登录参赛队号逐字节相同，长度 1–64 UTF-8 字节；`request_id` 长度 1–128 UTF-8 字节；二者不允许控制字符和不可见格式字符。频道 1–20，`1.0` 这样的整值 JSON number 也合法，布尔值不是频道或坐标。

`measure_result` 只有 `direction`、`near`、`no_signal`。`clear_result` 只有 `success`、`no_target_in_range`。未知字段不是忽略，而是 `accepted=false`；缺字段、非法坐标/频道、非法标识符等是 HTTP 400。路径必须精确匹配，不加尾斜杠或查询串。

## 计时与状态

一次成功接受的检测：

`移动直线距离 / 5 + (与当前测向频道不同时为 1，否则为 0) + 5` 秒。

一次成功接受的清除尝试：

`移动直线距离 / 5 + (成功为 5，未发现为 3)` 秒。

清除失败仍会移动至请求位置并产生 3 秒光学定位耗时。`/clear` 的频道只选择目标，绝不改变测向机频道，也不产生切换耗时。`near` 与 `no_signal` 仍各花 5 秒检测时间。所有移动均按上一次被接受的 `/measure` 或 `/clear` 的位置计算。

`/enter` 和 `/exit` 本身不增加虚拟时间；虚拟时钟允许小数，官方说明按微秒累计。`accepted=false` 表示动作未生效，其响应中的 `virtual_time_s=0` 不能用于覆盖真实累计时钟。

题面示例的累计虚拟时刻必须依次为：

| 动作 | 累计秒数 |
|---|---:|
| `/enter` | 0 |
| 在 `(300,400)` 测频道 1 | 105 |
| 原地测频道 2 | 111 |
| 到 `(300,0)` 尝试清除频道 3，未发现 | 194 |
| 原地测频道 2 | 199 |
| `/exit` | 199 |

完整任务耗时可交叉核对为 `L/5 + 5M + S + 5K + 3F`，其中 L 为总路程，M 为检测数，S 为实际测向切换数，K 为成功清除次数，F 为未发现的清除尝试次数。

## 幂等与异常恢复

每个新动作使用新 `request_id`。仅在响应丢失、连接超时等情况下重试完全相同的动作时，复用原路径、全部请求内容及原 ID。相同 ID 和内容返回第一次完整响应，不再次执行或计时；同 ID 改路径、位置、频道等内容是 HTTP 409。不同新动作必须串行等待完整响应。结构错误、未知字段及身份不匹配不占用 ID。

客户端用非重入动作锁拒绝第二个并发调用，不发送并发请求。网络失败时最多重试 `max_retries` 次，所有尝试使用原请求，退避时间受真实截止约束。HTTP 429/500/502/503/504 同样只按原 ID 有界重试；HTTP 409 立即报错并保留未决动作。HTTP 400 等确定拒绝不重试，也不修改本地位置和时钟。

如果重试后仍未拿到可用响应，动作可能已经执行。客户端保留 `pending_request`，并拒绝所有新动作；只有 `retry_pending()` 能恢复同一动作，禁止靠换新 ID 再执行来“恢复”。这也适用于清除：原动作已经成功时，换 ID 重试会返回未发现，错误地造成目标未清除的记录。

接口未开放、测试超时、中止或结束后，连接可能直接关闭而无 JSON。客户端不能凭断线推断动作成功或失败，也不能在结束后调用 `/exit` 查询结束原因。特别是 `/exit` 已执行但响应丢失时，真实服务可能已经关闭，缓存响应未必能再取回；客户端保留“不确定”状态，而不伪称成功。正式结束原因需从官方界面及日志核对。

## 两种时钟与截止

官方准备数据后进行 5 秒倒计时，然后开放 25 分钟窗口；`/enter` 成功后程序最长运行 20 分钟，以较早截止为准。进入时返回的 `remaining_real_duration_s` 是实际可用完整秒数，不一定是 1200。虚拟任务上限 360000 秒（100 小时）。截止前已完整到达并登记的唯一动作允许完成，截止后新动作不执行。

客户端 `deadline` 使用单调时钟，定义为“首次 `/enter` 传输开始时刻 + 返回的剩余秒数”。这样响应传输、缓存重试和返回延迟不会凭空延长预算。它是保守截止，可能略早于服务实际截止；若晚进入而返回 0，客户端停止新动作。每次检测的 5 秒为虚拟时间，本地或 HTTP 客户端都不主动等待 5 秒。

## 实现接口

```python
from bsolver.protocol import RobotClient, HTTPTransport
from bsolver.simulator import Source, LocalSimulator

# 独立自建案例，只作本地测试；一个源是单元测试夹具。
env = LocalSimulator([Source(1, (100.0, 0.0), radius=1000.0)], error_mode="correlated")
client = RobotClient(transport=env, robot_id="local-team", log_path="local_actions.jsonl")
client.enter()
result = client.measure(1, (0.0, 0.0))
client.clear(1, (100.0, 0.0))
client.exit()
client.close_log()
# 仅评价器持有 env 并读取统计，策略只持有 client。
score = env.summary()

# 官方网络调用由外层明确启动；这里只演示构造，不发送动作。
official = RobotClient(robot_id="实际参赛队号", transport=HTTPTransport())
```

客户端方法 `enter()`、`measure(channel, position)`、`clear(channel, position)`、`exit()` 返回已验证的原始成功响应字典。`position` 可以是两元坐标或恰含 `x,y` 的字典。`accepted=false` 抛 `RequestRejected`，原响应在异常 `.response`；HTTP 错误带 `.status_code` 和 `.response`。`TransportError` 表示结果尚不确定，`DeadlineExceeded` 表示本地不再发送，`PendingActionError` 要求恢复原动作。

状态：`position`、`current_channel`、`virtual_time`、`cleared_channels`、`cleared_count`、`entered`、`exited`、`deadline`；剩余时间由 `remaining_real_time()` 返回。`stats` 包含 `walk_distance`、`switches`、`measures`、`clear_attempts`、`successes`、`failures` 和各项时间。

`history` 保存每次传输尝试；设置 `keep_history=False` 可避免大批合成测试保留内存日志。若设置 `log_path`，每个尝试同步追加 JSONL 并刷新，记录原请求、响应或异常、尝试序号、墙钟与单调时钟、已确认状态。本地日志失败抛 `JournalError`，不会因此重复执行已经确认的动作。`close_log()` 与上下文管理器退出只关闭文件，不隐式发送 `/exit`。

## 本地模拟器边界

`LocalSimulator(sources, ...)` 本身就是 `transport(path, body) -> response`。源参数仅保留在环境中，公开端点不返回位置、数量、接收半径或定向方向。`summary()` 是评价器专用汇总；`public_trace()` 仅含请求和公开响应。Python 的对象封装不是对恶意反射的安全隔离，程序架构还应确保策略代码没有环境真值、评价器统计或随机案例对象作为输入。

正常合成案例用 `generate_sources(seed, count=None, directional_fraction=..., minimum_radius=False)` 生成，源数 10–16、频道唯一，位置在圆内。它使用自行声明的均匀面积位置抽样及半径/方向抽样，不能称为官方生成规律。环境可接受更少源用于边界单元测试，`enforce_case_size=True` 可要求竞赛规模。

误差模式：

- `deterministic`：对种子、频道、精确位置做稳定哈希，固定点重复不变。
- `correlated`：由平滑空间函数产生相关误差，尺度默认 150 米，范围仍在 ±1°。
- `extreme`：空间分块内为 +1° 或 −1°，用于最坏符号和跳变边界。
- `zero`、`positive`、`negative`：零误差、恒 +1°、恒 −1° 的测试夹具。

接口读数先加误差、再保留两位小数、再归一化到 `[0,360)`。零距离定向测点采用“源属于自身闭半平面，返回 near”的明确本地约定；题面没有详细定义零向量方位，策略的覆盖证明不应依赖这个退化点。方向半平面比较只加浮点运算量级的边界容差。

本地移动耗时四舍五入至最近微秒后累计（Python `round` 的半偶舍入），这落实了微秒计时，但官方没有公布恰半微秒时的具体舍入算法。跨实现核对时允许微秒级差异，不修改题面动作成本。

故障注入支持 `response_drop_ids`、`response_drop_indices`、`drop_next_response()` 和回调 `drop_response_after_execute(path, body, response)`。这些故障发生于动作执行且缓存响应之后，验证重试是否重复扣时或重复清除；正常缓存重放不再次注入同一故障。默认退出后端点关闭；可选 `replay_cached_after_close=True` 仅用于测试缓存仍可达的另一恢复分支。

`handle_json(...)` 用于在本地验证重复键、BOM、方法、内容类型、体积、层数等线格式规则，不启动监听服务。测试中的 HTTP 服务使用操作系统分配的临时回环端口，从不使用官方 2026 端口。

## 正式交付事实

第三、第四问各有三次正式机会，启动成功后占用，中止不退回。演练次数不限但仍需登录联网。每问正式测试表填写案例编码、清除数、平均定位清除时间和程序运行时间；六次正式日志应原样导出并纳入支撑材料，不能用自建测试 JSONL 替代官方加密日志。

正式界面不显示总数真值；未知源数下，不能清除 10 个就宣布全清。每个未解决频道需要搜索排除证书，或已成功清除 16 个利用总数上界结束。演练完成后能显示总数及全向/定向数量。
